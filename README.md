# Amazon ABA 热门搜索词分析器 PWA

版本：1.9.2
在线地址：https://tbymxy.github.io/amazon-aba-single-file-analyzer/

## 使用

1. 使用最新版 Firefox、Chrome 或 Edge 打开在线地址。
2. 选择统一的“导入”入口，可一次选择一份或多份、多站点、多周次 CSV，也可以日后继续追加。
3. 网页会流式提取分析所需的四个字段，并以分页二进制格式保存在当前浏览器中；刷新或重新打开无需再导入。
4. 通过“站点 / 起始周 / 结束周 / 查看周 / 对比周”切换数据。默认打开结束日最新的报告。
5. Chrome / Edge 可通过“安装应用”将它安装为独立 PWA 窗口；Firefox 桌面版可直接收藏并使用在线页面。在支持 Service Worker 的环境中，页面外壳可离线打开。

## 数据与功能

- 支持 US、CA、MX、GB、DE、FR、IT、ES、JP、AU。
- “导入”同时覆盖单份、两份对比和批量导入；恰好选择两份同站点报告时自动进入对比。
- 从文件名前缀识别站点；无前缀时会要求输入站点，不根据搜索词语言猜测。
- 周数与日期只从 CSV 第一行识别，标准化为 `周 N | YYYY-MM-DD - YYYY-MM-DD`。
- `TOP3点击` 和 `TOP3转化` 分别为前三名商品的点击份额、转化贡献占比之和；空值按 0 计算。
- 两周对比以“旧排名 − 新排名”计算涨跌；旧周不存在的词记为 0。
- 保留关键词、排名、TOP3 上限、涨跌区间筛选，多列三态叠加排序，以及双栏分页。
- 每页 100 个物理行，左右各 100 条，最多显示 200 条，不一次渲染整份报告。
- 1GB 以上报告使用流式读取和增量 SHA-256，不再把完整 CSV 解码成一个巨型字符串。
- 新导入报告使用 OPFS 二进制分页存储；默认浏览、页码跳转只读取当前页，筛选与排序在独立 Worker 中执行。
- 批量导入遇到单份损坏文件时会记录失败原因并继续处理其余文件；导入期间可随时取消，且不会并发启动第二个导入任务。
- 每个搜索词的“排名趋势”使用当前站点和起止周范围，按时间从旧到新显示 ABA 排名。
- 排名数字越小折点越高；缺失搜索词的周次留空并断开折线，不当作排名 0。
- 悬停折点显示周次、日期和准确排名；点击小图可打开详细趋势图，当前查看周使用蓝色强调。
- 趋势仅查询当前页最多 200 个词，并在 Worker 中读取二进制排名索引；完整周索引采用最多2份的LRU缓存，避免美国站全年趋势占用约1.6GB内存。
- 趋势索引缺失或损坏时会从本地分析数据自动重建，不要求重新选择原始CSV。
- 点击搜索词打开对应站点 Amazon 搜索；左侧图标打开对应地区 Google Trends。
- 导入前以站点、文件大小和“首部＋1/4＋中部＋3/4＋尾部”分段指纹筛选。对同文件名、同大小、同修改时间且指纹一致的已导入文件直接跳过，不再完整读取 1 GB 以上报告。
- 改名、修改时间变化或指纹可疑的候选仍流式计算完整 SHA-256；必须执行完整校验时使用 8 MB 分块，且后续解析直接复用该哈希，不再重复计算。
- 1.9.1 及更早报告重新选择同一原文件时，可使用现有元数据快速跳过，并自动补充新版分段指纹；缺少可靠文件身份元数据时仍回退到完整 SHA-256。
- 完全相同的文件按站点、周结束日和 SHA-256 跳过；同站点同周的不同版本会询问是否替换。
- 支持中文、英文、德文、法文、意大利文、西班牙文和日文常见周次及核心字段名称。

## 本地持久化说明

- CSV 不会上传到 GitHub 或其他服务器，原始 CSV 也不会复制到网站。
- IndexedDB 保存报告目录；OPFS 保存新版 `.aba2` 分页分析数据、趋势二进制索引，并继续兼容旧版 gzip 分析数据。
- 1.7.0 及更早版本已经导入的报告无需重新导入，可继续加载、对比、查看趋势和删除。
- 1.4.0 已导入的报告不需要重新选择 CSV；首次显示趋势时会在后台逐份建立索引，页面会显示进度。
- 数据与“网站域名 + 当前浏览器配置文件”绑定，不会跨电脑或跨浏览器自动同步。
- 无痕模式、清除该站点数据、删除浏览器配置文件，都会导致已导入数据丢失。
- 网页会申请持久存储；是否批准由浏览器决定。安装 PWA、保持站点活跃并避免手动清理站点数据，可降低被浏览器回收的风险。
- 建议保留原始 CSV 作为备份。
- “本地数据”可按站点筛选，动态显示报告数量、源报告原始大小（参考）、本地分析数据和趋势索引占用空间。
- 启动和导入前会检查分析文件是否存在及格式是否有效；缺失或损坏的报告显示警告，重新导入同一CSV即可修复。
- 支持单选、多选或全选当前筛选结果后批量删除；删除会清理报告目录、OPFS 分析数据、趋势索引及内存趋势缓存，但不会删除电脑原位置的 CSV。
- 本地数据页会识别未被报告目录引用的孤立缓存，用户确认后可一键清理。
- Chrome / Edge 优先使用文件夹备份：“导出备份”将分析数据、趋势索引、`reports.json` 和说明文件复制到普通 Windows 文件夹；恢复时可选该文件夹或其上级文件夹。
- Firefox 不支持 Chromium 的文件夹选择 API，页面会自动切换为兼容方式：小型数据库下载为单个 `.aba-backup` 备份包；数据量超过 512 MB 时按数据文件拆分下载，避免生成超大 Blob 占用内存。
- Firefox 恢复 `.aba-backup` 时只需选择该文件；恢复拆分备份时，进入备份文件夹后按 `Ctrl+A` 全选 `reports.json`、`.aba2`、`.trend.bin` 等文件。Chrome / Edge 也可通过“选择备份文件”恢复这两种 Firefox 备份。
- 超大备份恢复使用 `File.stream().pipeTo()` 直接写入 OPFS，不会将 1 GB 级数据文件整份读入内存；缺少趋势索引时可继续恢复并在首次查询时自动重建。
- 由于浏览器安全限制，网页不能直接用 Windows 资源管理器打开 OPFS 内部目录，请通过导出备份查看文件。

直接通过 `file://` 打开本地 HTML 时，部分浏览器不提供 OPFS/PWA 能力；建议使用上述 HTTPS 在线地址。
